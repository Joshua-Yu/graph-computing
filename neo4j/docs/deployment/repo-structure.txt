Conventions
-----------
- "Party" is the canonical graph term (spec/model/, generated/cypher/, src/). "Customer"
  is kept only where it mirrors a source system's own name (the source side of spec/contracts/). The mapping
  is defined once, in docs/01-overview/glossary.md.
- Graph and Cypher tests both live in tests/graph/.
- Risk scoring lives in src/risk/scoring/; Hume workflows in orchestration/hume/workflows/.
- spec/schemas/ holds one format only: the one the Kafka schema registry uses. A Kafka
  contract references its registry schema and does not restate the fields.
- test-data/ and notebooks/ are synthetic data only; notebook outputs are stripped
  before commit (.pre-commit-config.yaml).

Data contract conventions (full rules: docs/05-data/data-contract-guideline.md)
-------------------------------------------------------------------------------
- spec/ is the only place a model, source, mapping, SLA or access rule is defined.
  Everything under generated/ is derived from it by tools/contractctl.
- There are three layers. A source contract describes one dataset and maps it to the
  canonical model, with every transformation. The canonical model in spec/model/ standardises
  terms, attributes and relationships. The graph is projected from the canonical model by its
  graph annotations, with no value transformation.
- One contract per dataset. A source table delivered as a Day 0 extract and as CDC events has
  two contracts in the same spec/contracts/<system>/<table>/ folder, named <table>-day0 and
  <table>-cdc. Folders use the source's own names, not graph terms.
- Each contract is authored as a workbook (<name>.contract.xlsx) and imported to YAML beside
  it. CI re-imports the workbook and fails if the result differs from the committed YAML.
- A transform named in a mapping must exist in spec/transforms/transforms.yaml and be
  implemented in src/common/.
- Data the graph produces (scores, alerts, cases) has no source, so it is described by a
  product.yaml under spec/products/.
- Access is defined once, by classification, in spec/model/access.yaml.
- Environments are dev, sit, nft and prod. UAT is served by read replicas of the prod cluster,
  so it has no environment folder and nothing is deployed to it separately.
- generated/ is committed. contract-ci.yml regenerates it on every pull request and fails
  if the result differs from what is committed. Fix the spec or the generator, never the
  generated file.
- generated/cypher/migrations/ is the only executable source for constraints and indexes.
  Migrations are append-only: a model change produces a new numbered migration, and an
  applied migration is never rewritten.
- Logic that cannot be declared stays in src/ and is referenced by name:
  transforms in src/common/, staging steps in src/ingestion/transformation/, matching in
  src/ingestion/entity-resolution/.
- src/ingestion/ holds the runtime that executes generated row builders, loaders and quality
  checks. It contains no source-specific field names.
- infrastructure/kafka-connect/ and monitoring/ hold hand-written platform configuration;
  per-source connector configs and SLA alerts are in generated/.
- Environment values (hosts, topics, credentials, thresholds that differ by environment)
  live in config/<env>/ and never in spec/.
- A breaking contract or model change needs a major version bump and approval from the
  CODEOWNERS of every affected contract. contractctl diff decides what counts as breaking.
